## Executive Summary

The service has a working pipeline and good engineering bones — parameterised SQL, a write-serialising semaphore, a structured shard model, Negotiate auth, structured Serilog logging — but it is **not safe to deploy outside a trusted lab network as-is**. The dominant risk is a confluence of three Critical issues that compound: Kestrel listens on `0.0.0.0:5100` over **plain HTTP** while using Windows Negotiate (NTLM credential exposure on the wire); `[Authorize(Policy="AuditorOnly")]` on minimal-API static handlers is **silently ignored** so the role guard the codebase appears to implement does not exist at runtime; and `GET /api/jobs/{jobName}/manifest` performs **unrestricted path traversal** via `Path.Combine` on an unvalidated route segment. Together these mean any domain account on the network can read arbitrary files (including `web.config`, secrets) over an unencrypted channel that also leaks NTLM hashes for relay. Beneath the security layer there are three Critical concurrency defects in the SQLite shard layer (use-after-dispose between `ShardEvictionService` and in-flight queries; `_readConn` shared across worker tasks; non-thread-safe DCL fast-path in `QueryRepository`) that will cause production instability under load. Configuration has one Critical: the install script never registers the EventLog source, so all Warning/Error log writes silently vanish — meaning ops will not see the failures these other defects produce.

**Start here:** Fix the three intertwined Critical security findings before anything else — bind Kestrel to `127.0.0.1` (or add TLS), correct the AuditorOnly attachment to use `.RequireAuthorization("AuditorOnly")` on the chained `MapGet`, and validate `jobName` against `ShardRegistry` before any `Path.Combine`. Without those, every other fix is moot.

## What looks good

- **SQL is fully parameterised.** No string-concatenation injection in the data path. The `sort`/`ORDER BY` use is the only non-parameterised path, and even there a ternary restricts the set — though the endpoint should still allow-list explicitly (#21).
- **Per-job sharded SQLite** model is sound: each job owns its own `audit.db` under `.audit/`, opened `Mode=ReadOnly` for queries and `Mode=ReadWriteCreate` for writes. The model isolates blast radius and avoids cross-job lock contention.
- **Negotiate authentication** is correctly wired and the fallback policy of `RequireAuthenticatedUser` means anonymous access is impossible. The bug is only that the *elevated* `AuditorOnly` policy isn't actually applied (#2), not that auth is missing.
- **Structured logging** via Serilog with three sinks (Console / rolling File / EventLog) and correct `outputTemplate` configuration. Most call sites use proper templated properties (the few that don't are flagged).
- **No fire-and-forget on the hot path.** Audit-event writes flow through `Channel<>` consumers with a write semaphore — the asynchronous boundary is in the right place.
- **Schema migrations** (`MigrateSchema`, `AlterTableAddColumns`) are idempotent and survive restart — the structural concern is interpolation, not correctness.
- **HTTP method discipline.** Every endpoint is `GET`; no state-changing operations are performed via GET.
- **`JobDiscoveryService`** thread-safety pattern (`volatile IReadOnlyList<JobSummary>` swap-on-rebuild) is verified correct — a textbook lock-free read pattern.

## Recommendations

> **Start here:** Disable network exposure and fix authorisation before anything else — bind Kestrel to `127.0.0.1` (or front it with TLS), change every `[Authorize(Policy="AuditorOnly")]` attribute to a chained `.RequireAuthorization("AuditorOnly")` on the `MapGet`/`MapPost`, and validate `jobName` against `ShardRegistry.Contains(jobName)` before any `Path.Combine`. Without those three, every other fix is layered on top of an open door.

### Immediate (fix before next deploy)

1. **Network surface (#1)** — Change `Kestrel:Endpoints:Http:Url` to `http://127.0.0.1:5100`, or add an HTTPS endpoint with a real certificate. If the service is genuinely intended for cross-machine query, Negotiate over plain HTTP is unacceptable; either add TLS or restrict to loopback and require a reverse proxy that terminates TLS.
2. **AuditorOnly is a no-op (#2)** — `[Authorize]` attributes on static minimal-API handler methods are silently ignored. Replace every such attribute with `.RequireAuthorization("AuditorOnly")` chained onto the `MapGet`/`MapPost` call. Audit *every* endpoint to confirm the policy was intended (the codebase shape suggests it was).
3. **Path traversal on manifest (#3)** — Validate `jobName` against `ShardRegistry` *before* using it in any `Path.Combine`; reject names containing `\`, `/`, `..`, or any character outside `[A-Za-z0-9._-]`. Same fix applies to FileHistory's prefix check (#22) — append `Path.DirectorySeparatorChar` to `jobRoot` before `StartsWith`.
4. **Information disclosure in DTOs (#4, #5)** — Remove `ShardPath` from `JobSummary` and `Filepath` (absolute) from `AuditEventSummary` / `AuditEventDetail`. Use `RelFilepath` (job-relative) only.
5. **SQLite use-after-dispose (#6, #7, #8)** — Three related defects:
   - Move the `_disposed` check **inside** the write semaphore in `SqliteRepository`.
   - Stop sharing `_readConn` across worker tasks; either give each worker its own connection or serialise worker reads.
   - Replace the DCL fast-path in `QueryRepository` with a `ConcurrentDictionary<string, Lazy<SqliteConnection>>` and arrange disposal via a coordinated reference-count or a `SemaphoreSlim` per shard so `CloseShard` can wait for in-flight readers.
6. **Silent FileEra corruption (#9)** — Replace `catch (Exception) {}` in `Program.cs:91` with a logged catch and consider failing the settle-window task loudly. This bug means production audit data is silently mis-tagged after any transient SQLite or disk error.
7. **EventLog never registered (#10)** — Add `New-EventLog -LogName Application -Source FalconAuditService -ErrorAction SilentlyContinue` to `install.ps1`, *before* the service is started. Without this, every Warning/Error log entry the rest of these fixes generate will silently disappear.
